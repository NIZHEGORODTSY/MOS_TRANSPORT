# МосТранспорт — предиктор изменений в графике движения

Система в реальном времени принимает телеметрию NDTP, накладывает её на плановое расписание
и за **10–15 минут** до прибытия на остановку прогнозирует задержку каждого ТС.
Диспетчер видит на карте, кто опаздывает, кто в зоне риска и кто идёт по графику.

## Архитектура

```
 NDTP-поток                ┌──────────────────────── docker compose ────────────────────────┐
 (replayer / эмулятор) ──► │ backend  :9201 NDTP  ──► TelemetryStore (история за час)        │
                           │   │  раз в 30 с: история + расписание ──► ml  /set_context      │
                           │   │               точки прогноза       ──► ml  /predict          │
                           │   └── /api, /ws/vehicles (1 с) ◄── frontend (nginx) ◄── браузер  │
                           └────────────────────────────────────────────────────────────────┘
```

| Сервис | Папка | Что делает |
|---|---|---|
| `ml` | `ml_service/` | ML-ядро: ансамбль CatBoost + PyTorch GRU, API `/set_context`, `/predict`, `/health` |
| `backend` | `backend/` | FastAPI: приём и парсинг NDTP (TCP 9201), сопоставление с расписанием, цикл прогноза, REST + WebSocket, Swagger |
| `replayer` | `backend/ndtp/replayer.py` | исторический датасет → живой NDTP-поток (тот же образ, что backend) |
| `frontend` | `frontend_2_0/` | BI-дашборд (React + Mapbox GL); nginx раздаёт его и проксирует `/api`, `/ws`, `/docs` в backend |
| `emulator` | — | эмулятор NDTP организаторов (необязательный профиль) |

Наружу открыт только порт дашборда. ML-сервис доступен лишь внутри сети Docker.
Логин диспетчеров и геометрия маршрутов берутся из базы команды (PostgreSQL на сервере).

## Запуск

Нужен Docker с Compose v2.

```bash
cp .env.example .env                  # WEB_PORT, REPLAY_SPEED, API_PORT, NDTP_PORT
cp backend/.env.example backend/.env  # DATABASE_URL базы команды (для логина и маршрутов)
docker compose up -d --build
```

* Дашборд: <http://localhost:8080> (порт — `WEB_PORT` в `.env`)
* Swagger: <http://localhost:8080/docs>
* Состояние прогноза: <http://localhost:8080/api/predictions>

Первый прогноз появляется, когда у ТС накопится 15 минут телеметрии: на `REPLAY_SPEED=1` —
через 15 минут, на `REPLAY_SPEED=30` — через 30 секунд.

## Инструкция для жюри

### Как подать поток

**Исторический датасет (по умолчанию).** Сервис `replayer` поднимается вместе с системой и
проигрывает `ml_data/traffic_test.csv` (06.01.2026 с 08:00 МСК) как поток NDTP: одно
TCP-соединение на терминал, рукопожатие и навигационные пакеты с исходными метками времени.
Скорость — `REPLAY_SPEED` в `.env` (1 — реальное время), по окончании данных начинает заново.

**Эмулятор организаторов.**

```bash
docker load -i ndtp-telemetry-emulator.tar
docker compose --profile emulator up -d
curl -X POST http://localhost:8000/api/emulator/start -H "Content-Type: application/json" -d '{"units": 16, "interval_ms": 1000}'
```

Бэкенд настраивает эмулятор слать пакеты себе на `backend:9201`. Остановить: `POST /api/emulator/stop`.
Любой внешний источник NDTP можно направить на `127.0.0.1:9201` хоста (`NDTP_PORT`);
API и Swagger напрямую — `127.0.0.1:8000` (`API_PORT`).

### Где смотреть прогнозы и алерты

* **Карта.** Точка ТС — цвет маршрута. Кольцо вокруг — прогноз задержки на остановке через 10–15 мин:
  🔴 опаздывает (> 3 мин), 🟡 риск опоздания (1–3 мин), 🟢 успевает (± 1 мин), ⚪ раньше графика (> 1 мин).
  Мелкие точки без кольца — ТС без прогноза (нет расписания или мало телеметрии).
* **Легенда** в боковой панели: сколько ТС в каждом статусе прямо сейчас.
* **Список ТС**: группы «С прогнозом / Без прогноза / Нет связи», опаздывающие — сверху.
* **Карточка ТС** (клик по ТС): прогноз задержки, целевая остановка, плановое и прогнозное время,
  график отклонения от графика за последний час.
* **API**: `GET /api/predictions` — прогнозы и состояние цикла (`elapsed_s`, ошибки ML),
  `GET /api/predictions/{tr_id}/history` — ряд прогнозов ТС, `GET /api/telemetry/stats` — приём NDTP.

## Модель

Для ТС в момент T прогнозируется задержка на первой остановке, плановое время которой попадает
в `(T+10 мин, T+15 мин]`. Признаки считаются только по телеметрии до T и плановому расписанию:
map matching на «нитку графика», текущее отклонение и его тренд, скорость и простой в окнах
2–10 мин, профиль перегонов впереди по другим ТС. Ансамбль: 0.4 × GRU по последовательности
состояний ТС + 0.6 × CatBoost по табличным признакам. Подробнее — `ml_service/README.md`.

| | MAE, с |
|---|---|
| baseline организаторов (`cur_dev_s`) | 93.4 (test) |
| ансамбль, отложенный test | 68.8 |
| ансамбль на живом потоке NDTP (69 прогнозов, 10 ТС) | 68.4 при 75.8 у «идёт по графику» |

Скор сабмита на платформе — 0.99.

## Производительность и надёжность

* Цикл прогноза по всему потоку (история за час + ~10 ТС) — **0.4–0.8 с**, инференс модели ≈2 мс на ТС;
  фактическое время последнего цикла — `elapsed_s` в `/api/predictions`.
* WebSocket рассылает состояние всех ТС раз в секунду; парсинг NDTP — 0.1–0.2 мс на пакет,
  статистика — `/api/telemetry/stats`.
* **ML-сервис недоступен** — бэкенд не падает: карта и телеметрия работают, последние прогнозы
  остаются с отметкой времени расчёта, после восстановления цикл продолжается сам.
* **Обрыв NDTP** — ТС показывается с последней известной позицией как «нет связи»,
  пакеты без GPS-фикса не затирают позицию, replayer переподключается каждые 5 с,
  если порт NDTP занят, приёмник повторяет попытку каждые 5 с, не роняя API.
* Все сервисы с `restart: unless-stopped`; бэкенд и ML с healthcheck.

## Дополнительные возможности

* Map matching координат на «нитку графика» ТС с учётом курса и отстоя (ML-ядро).
* Ансамбль CatBoost (табличные признаки) + PyTorch GRU (последовательность телеметрии).
* Собственный NDTP-стек: парсер с CRC-16 и ресинхронизацией, приёмник, replayer датасета.
* Цветовая индикация риска, график отклонения по каждому ТС, группировка и сортировка по риску.

## Разработка без Docker

```bash
cd backend && python -m venv .venv && .venv/Scripts/pip install -r requirements.txt
.venv/Scripts/python -m uvicorn app.main:app --port 8000
.venv/Scripts/python -m ndtp.replayer --speed 30
cd frontend_2_0 && npm install && npm run dev   # http://localhost:5173, /api и /ws проксируются на :8000
```

ML-сервис локально: `cd ml_service && uvicorn app:app --port 8001`, бэкенду — `ML_SERVICE_URL=http://127.0.0.1:8001`.
