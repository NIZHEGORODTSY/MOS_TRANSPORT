## Сверх списка

**Поток и надёжность**
* Собственный стек NDTP: парсер с проверкой CRC-16/Modbus и ресинхронизацией по сигнатуре после мусора в потоке, асинхронный TCP-приёмник, 38 мкс на пакет.
* Replayer: исторический датасет превращается в живой поток NDTP — отдельное соединение и рукопожатие на терминал, исходные метки времени, настраиваемая скорость, повтор по кругу, переподключение при обрыве.
* Управление эмулятором организаторов через API бэкенда (`/api/emulator/start|stop`).
* Деградация без падения: при недоступном ML остаются последние прогнозы, при обрыве NDTP — последние позиции ТС; всё восстанавливается само.

**Модель и честность прогноза**
* Горизонт соблюдается на потоке: цель — первая остановка с плановым прибытием через 10–15 минут от момента последнего пакета ТС.
* Защита от утечек: признаки только по телеметрии до момента T и плановому расписанию; синтетические ТС (копии реальных) и факты прибытий в инференс не попадают. Найденную утечку в данных организаторов (факты validate в `test/schedule.csv`) мы описали и не используем.
* Контроль качества на живом потоке: `tools/benchmark.py` сравнивает прогнозы цикла с фактическими прибытиями.

**Дашборд**
* Четыре уровня риска (опаздывает / риск / успевает / раньше графика) кольцом вокруг ТС, при этом цвет точки сохраняет цвет маршрута.
* Легенда со счётчиками ТС в каждом статусе, список с группами «С прогнозом / Без прогноза / Нет связи» и сортировкой по риску.
* Карточка ТС: прогноз, целевая остановка, «план → прогноз», график отклонения от графика за час.
* Маршруты по реальным дорогам (сервер маршрутизации на osmnx) с постепенной подгрузкой через SSE и запасным вариантом прямыми линиями.
* Обновление в реальном времени по WebSocket раз в секунду; вход диспетчера с паролями в bcrypt.

**Эксплуатация**
* `docker compose up` поднимает всю систему; наружу открыт один порт (nginx проксирует API, WebSocket и Swagger), ML-сервис изолирован во внутренней сети; healthcheck и автоперезапуск.
* Воспроизводимый замер производительности и качества (`backend/tools/benchmark.py`).
* Swagger с описаниями и примерами ответов, документация по коду на Sphinx.
