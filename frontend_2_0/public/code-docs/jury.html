Инструкция для жюри¶

Как подать поток телеметрии, где увидеть прогнозы и алерты, как открыть дашборд и метрики.

1. Открыть систему¶

Развёрнутый стенд: адрес и учётная запись диспетчера указаны в форме сдачи решения.

Локально (нужен Docker с Compose v2, подробности — в README):

git clone https://github.com/NIZHEGORODTSY/MOS_TRANSPORT.git && cd MOS_TRANSPORT
cp .env.example .env
cp backend/.env.example backend/.env   # вписать DATABASE_URL из формы сдачи
docker compose up -d --build

Что

Адрес (локально)

Дашборд

http://localhost:8080

Swagger (API бэкенда)

http://localhost:8080/docs

Документация по коду (Sphinx)

http://localhost:8080/code-docs/

Прогнозы и состояние цикла

http://localhost:8080/api/predictions

Статистика приёма NDTP

http://localhost:8080/api/telemetry/stats

На развёрнутом стенде адреса те же, с его доменом вместо localhost:8080.

2. Подать поток¶

Бэкенд принимает NDTP по TCP на порту 9201. Подойдёт любой из трёх источников, их можно включать одновременно.

Исторический датасет — включён по умолчанию¶

Сервис replayer стартует вместе с системой и проигрывает ml_data/traffic_test.csv (06.01.2026, с 08:00 МСК) как настоящие терминалы: отдельное TCP-соединение на терминал, рукопожатие, навигационные пакеты с исходными метками времени. Когда данные кончаются, начинает заново.

Скорость — REPLAY_SPEED в .env: 1 — реальное время, 30 — час данных за 2 минуты. Чтобы быстрее увидеть прогнозы:

REPLAY_SPEED=30 docker compose up -d replayer

Эмулятор NDTP организаторов¶

docker load -i ndtp-telemetry-emulator.tar          # образ из датасета организаторов
docker compose --profile emulator up -d

Затем в Swagger (/docs) → Эмулятор → POST /api/emulator/start → Try it out → Execute (по умолчанию 16 терминалов, пакет раз в секунду) или из консоли:

curl -X POST http://localhost:8000/api/emulator/start -H "Content-Type: application/json" -d '{"units": 16, "interval_ms": 1000}'

Бэкенд сам настраивает эмулятор слать пакеты на свой приёмник. Терминалы эмулятора появляются на карте серыми точками маршрута «—»: у них нет расписания, поэтому прогноз для них не строится. Остановить — POST /api/emulator/stop.

Свой источник NDTP¶

Направьте его на 127.0.0.1:9201 хоста (порт — NDTP_PORT в .env). Формат — по спецификации организаторов (docs/Emulator-and-Telematic-Packets-Specification.md в датасете): рукопожатие NPH-типа 100, затем навигационные пакеты NPH-типа 101 с ячейкой G6CellNav00. Счётчики пакетов и ошибок CRC — в GET /api/telemetry/stats.

3. Где прогнозы и алерты¶

Прогноз строится для каждого ТС с расписанием: задержка на первой остановке, плановое прибытие на которую через 10–15 минут. Первый прогноз появляется, когда у ТС накопится 15 минут телеметрии (на REPLAY_SPEED=1 — через 15 минут после старта), дальше пересчёт раз в 30 секунд.

Карта. Точка ТС окрашена в цвет маршрута, кольцо вокруг — прогноз:

Мелкие точки без кольца — ТС без прогноза (нет расписания или мало телеметрии), полупрозрачные — нет связи.

Алерты в боковой панели:

  • легенда «Прогноз на 10–15 мин» — сколько ТС сейчас в каждом статусе;

  • список ТС — группа «С прогнозом» идёт первой, опаздывающие в ней сверху, с величиной задержки;

  • карточка ТС (клик по точке или строке списка) — прогноз задержки, адрес целевой остановки, «план → прогноз» по времени и график отклонения от графика за последний час.

Через API: GET /api/predictions — прогнозы всех ТС (delay_s, risk, остановка, плановое и ожидаемое время, момент прогноза at и горизонт horizon_s), GET /api/predictions/{tr_id}/history — ряд прогнозов ТС.

4. Метрики¶

  • Цикл прогноза: GET /api/predictions → status.elapsed_s — сколько занял последний пересчёт (история + запрос к ML), status.state — ok / warming_up / error.

  • Приём NDTP: GET /api/telemetry/stats — соединения, пакеты в секунду, ошибки CRC, среднее время разбора пакета.

  • Замеры и качество модели: PERFORMANCE.md; повторить замер — python -m tools.benchmark из папки backend.

5. Проверить надёжность¶

docker compose stop ml        # ML-сервис недоступен

Карта и телеметрия продолжают работать, /api/predictions → state: "error", последние прогнозы остаются с отметкой computed_at. После docker compose start ml цикл восстанавливается сам.

docker compose stop replayer  # обрыв потока NDTP

ТС сразу становятся «нет связи» (если соединение повисло без закрытия — через 30 с) и остаются на последней известной позиции. После docker compose start replayer терминалы переподключаются за несколько секунд, бэкенд при этом не перезапускается.
